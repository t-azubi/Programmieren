# Kommentare: warum und wofür

Kommentare erklären das **Warum**, nicht den offensichtlichen Code.

## Gute Kommentare

- beschreiben Entscheidungen und Randfälle
- erklären Workarounds
- dokumentieren Risiken und Annahmen

## Schlechte Kommentare

- wiederholen nur den Code
- sind veraltet
- enthalten irrelevante Infos

## Kurzregel

Wenn ein Kommentar nötig ist, weil der Code unklar ist, verbessere zuerst den Code.
